A Windows desktop application that converts PNG, GIF, and APNG images
into Minecraft Java Edition datapack ZIP files. The UI is built with
PySide6. Animation parsing, particle simulation, performance presets,
risk estimation, version-specific commands, and ZIP packaging are
organized into separate modules.

## Project Architecture

``` text
ParticleGenerator/
├── main.py                         # QApplication entry point
├── app_info.py                     # Application name and version
├── build.py                        # Generates the icon and builds a standalone EXE
├── ui/
│   ├── main_window.py              # Image import, parameter settings, and export UI
│   └── preview.py                  # Standalone image preview and particle simulation component
├── core/
│   ├── image_parser.py              # PNG/GIF/APNG loading, scaling, and transparent-pixel filtering
│   ├── particle_model.py            # Local-space particle and Pivot data models
│   ├── transform.py                 # Scaling, rotation, and execution-position offset pipeline
│   ├── rotation.py                  # Euler rotation mathematics
│   ├── coordinate_system.py         # World/executor/player-facing coordinate conversion
│   ├── renderer.py                  # Renders models as Minecraft function commands
│   ├── particle_generator.py        # Model-generation entry point for legacy calls
│   ├── datapack_builder.py          # pack.mcmeta, function files, and ZIP packaging
│   ├── performance.py               # Low/medium/high resolution and resource budgets
│   ├── prediction.py                # Estimates command count, file size, and execution risk
│   ├── app_config.py                # User configuration stored in AppData
│   ├── app_logging.py               # Rotating error logs
│   └── resource_paths.py            # Resource path checks for source and packaged builds
├── version/
│   ├── base.py                      # Version adapter interface
│   ├── registry.py                  # Supported-version registry
│   ├── mc1204.py                    # 1.20.4 command syntax and metadata
│   ├── mc1205.py                    # 1.20.5/1.20.6 adapter
│   └── mc121x.py                    # 1.21.x adapter
├── minecraft/
│   ├── mc1204_renderer.py           # 1.20.4 particle syntax
│   └── mc1205_renderer.py           # Particle syntax for 1.20.5+
├── editor/
│   ├── viewport.py                  # Rotatable, pannable, and zoomable 3D model viewport
│   ├── camera.py                    # Orbit camera
│   └── gizmo.py                     # XYZ coordinate gizmo
├── resources/
│   └── app_icon.ico                 # Application icon generated and embedded by the build script
├── build/
│   └── ParticleGenerator.spec       # PyInstaller single-file configuration
└── requirements.txt
```

The processing pipeline is:

`Image → ParsedImage → ParticleModel (local coordinates) → Visual Editing → Transform → MinecraftRenderer → DatapackBuilder → ZIP`

The default Pivot is at the bottom-left corner of the image. Right is
+X, and up is +Y. The model itself does not store Minecraft commands;
function text is generated by the version-specific renderer only during
prediction or export. To add support for a new version, register a
metadata adapter in `version/` and the corresponding command renderer in
`minecraft/`.

## Run Locally

Regular users can run `build/dist/ParticleGenerator.exe` directly
without installing Python. Developers only need Windows 10/11 and Python
3.10 or later on the build machine:

``` powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

## Build a Standalone EXE

PyInstaller cannot cross-build Windows executables from other operating
systems. After installing the dependencies on a Windows build machine,
run:

``` powershell
python build.py
```

The script automatically generates the application icon and then uses
the PyInstaller spec to build a single-file GUI application. The
software version is **1.3.0**. The output is located at
`build/dist/ParticleGenerator.exe`. PySide6, Pillow, and the application
icon are bundled with the program, so the target computer does not need
Python or any additional runtime environment. The first launch may take
a little longer while the bundled runtime files are extracted.

User configuration is stored in
`%APPDATA%\Minecraft Particle Image Generator\config.json`. Rotating
logs are stored in
`%LOCALAPPDATA%\Minecraft Particle Image Generator\logs\application.log`.

## Current Support

-   **Datapacks:** Minecraft Java Edition 1.20.4, 1.20.5, 1.20.6, and
    registered versions from 1.21 through 1.21.11. All supported
    versions use the `function/` directory. Versions 1.21.9 and later
    use the `min_format`/`max_format` metadata fields.
-   **Particles:** `minecraft:dust`, `minecraft:flame`,
    `minecraft:cloud`, and `minecraft:end_rod`.
-   Pixels with an alpha value of 0 are ignored; all non-zero alpha
    values are treated as visible pixels. Non-Dust particles do not
    support per-pixel RGB colors. Dust size ranges from 0.01 to 4.
-   Function paths for all supported versions use the format
    `data/<namespace>/function/<name>.mcfunction`.
-   The 3D viewport supports left-button rotation, right/middle-button
    panning, and mouse-wheel zooming. It displays a grid, XYZ axes, and
    the Pivot. Transformations, particle size, alpha, Pivot, and
    orientation mode can all be edited in the UI.
-   **Orientation modes:** fixed world orientation, inherit the function
    executor's orientation, or inherit the nearest player's view
    direction. The first two modes do not require `with block`. Model
    positions use relative coordinates in the execution context. View
    mode overrides the direction using `execute rotated as @p`.
-   After the Pivot, local points pass through XYZ scaling, Euler XYZ
    rotation, and execution-position offset, then are rendered as
    Minecraft `~` or `^` coordinates. For a normal function call, the
    execution position is the anchor at the selected Pivot; by default,
    this is the bottom-left corner.
-   Animation playback uses a temporary entity tag to preserve the
    starter's execution position and orientation. Players run the
    `start`/`stop` functions. Dust and other particle commands do not
    support per-particle alpha or sprite rotation. Alpha is used for
    model preview and to hide fully transparent particles.
-   For a static model, when running `/function <namespace>:<name>`, the
    current function execution position is the anchor at the selected
    Pivot. The bottom-left Pivot is the default. To explicitly use a
    player's execution context, run
    `/execute as @p at @s run function <namespace>:<name>`. Do not use
    `with block` for positioning; it is only used to pass block NBT data
    to macro functions.
-   **Performance presets:** Low mode scales the image down to a maximum
    of 128×128 and merges pixels by region. Medium mode supports up to
    500,000 pixels; High mode supports up to 1,000,000 pixels. Animation
    is limited to 120 frames, with a total pixel budget to control
    memory usage.
-   Animation frames loop automatically according to GIF/APNG frame
    durations. After generation, run
    `/function <namespace>:<name>/animation/start` to start playback and
    `/function <namespace>:<name>/animation/stop` to stop it.
-   Execution risk is estimated from the command count per frame and
    function text size. Exporting high-risk content requires
    confirmation. Particle simulation is an approximate rendering for
    layout and color preview, not a screenshot from the Minecraft
    client.
